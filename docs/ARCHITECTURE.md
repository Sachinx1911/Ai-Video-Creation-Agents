# Architecture

Status: **proposed** (Phase 0). Sections marked *(Phase N)* do not exist in code yet.

## 1. Shape: modular monolith + workers

```
┌──────────────────────┐   HTTP/JSON    ┌───────────────────────────────┐
│ apps/web (Next.js)   │ ─────────────► │ apps/api  FastAPI  (studio.*) │
│ dashboard, no secrets│                │  routes → services → db       │
└──────────────────────┘                └──────────────┬────────────────┘
                                                        │ SQL (jobs table = queue)
                       ┌────────────────────────────────▼───────────────┐
                       │ PostgreSQL: projects, assets, jobs, events ... │
                       └────────────────────────────────▲───────────────┘
                                                        │ claim (SKIP LOCKED) / heartbeat
                         ┌──────────────────────────────┴───────────────┐
                         │ studio.workers  (separate OS process(es))    │
                         │  handlers: asset.probe (P1), generate.* (P3),│
                         │  render.* (P4), qa.* (P5)                    │
                         └───────┬───────────────────────┬──────────────┘
                                 │ subprocess, shell=False│ HTTPS
                          FFmpeg / FFprobe        Provider adapters (cloud/local)
                                 │
                         storage root (local filesystem): projects/<id>/assets/...
```

- **API process**: validates input, writes DB rows, enqueues jobs. Never runs long media or AI work in a request.
- **Worker process(es)**: claim jobs from the `jobs` table with a lease; heavy work (rendering, generation polling) runs here. Several workers can run; rendering can get its own worker pool by job-type filter.
- **Web**: Next.js App Router. Talks only to the API. No API keys in the browser.

## 2. Python package layout (`apps/api/studio`)

| Package | Responsibility | Phase |
|---|---|---|
| `core` | settings (env), logging + secret redaction, safe path handling, errors | 1 |
| `db` | SQLAlchemy engine/session, ORM models, enums | 1 |
| `schemas` | Pydantic request/response + versioned contracts | 1+ |
| `services` | business logic (projects, assets, jobs, health) | 1+ |
| `api` | FastAPI routers (thin) | 1+ |
| `workers` | job runner loop, leases, retry policy, handlers | 1+ |
| `media` | ffprobe/ffmpeg wrappers (argument lists only) | 1 (probe), 4 (render) |
| `agents` | 12 agents, each: input schema, output schema, run(), error contract | 2–5 |
| `providers` | capability-based adapters: llm, image, video, speech, asr | 3 |
| `timeline` | timeline spec + validator + FFmpeg plan compiler | 4 |
| `orchestrator` | workflow state machine, dependency DAG, checkpoints | 5 |

Dependency rule: `api → services → db/media/providers`; `agents` never import `api`; providers never import `db`.

## 3. Job system (ADR-0002)

States: `queued → running → succeeded | failed | cancelled`, `running → awaiting_retry → queued`, `queued → cancelled`. `submitted` is represented by `queued` + `provider_job_id` for remote async jobs *(Phase 3)*.

- Claim: `UPDATE jobs SET status='running', locked_by, lease_expires_at … WHERE id = (SELECT id … WHERE status='queued' AND run_after <= now() ORDER BY priority, created_at FOR UPDATE SKIP LOCKED LIMIT 1)`.
- Heartbeat extends the lease; a job whose lease expires (worker crashed) is reclaimed → `queued` (attempt counted).
- Errors are categorised: `transient`, `rate_limited`, `provider_outage`, `invalid_request`, `auth`, `invalid_output`, `internal`. Only the first three are retried, with exponential backoff + jitter, up to `max_attempts`; then `failed` (dead letter, kept for inspection).
- Idempotency: optional unique `idempotency_key` per job; enqueueing the same key returns the existing job.
- Every transition writes a `job_events` row (append-only audit).

## 4. Storage and file safety

- One configured `STORAGE_ROOT`. Asset paths stored **relative** to it: `projects/<project_id>/assets/<asset_id>/<version>/<sanitised_name>`.
- All path joins go through `core.paths.safe_join`, which resolves and asserts containment (blocks `..`, absolute paths, drive letters, symlink escape).
- Uploads: size limit, extension + content sniff (ffprobe) validation, sha256 computed while streaming.
- Temp files under `STORAGE_ROOT/tmp/<job_id>` with cleanup on job end *(Phase 4 render temp)*.

## 5. Media execution safety

FFmpeg/FFprobe are called via `subprocess.run([...], shell=False, timeout=…)` with argument lists generated by code from validated models. AI output is never interpolated into commands; it can only populate typed fields (e.g. text overlays are written to files / escaped filter params).

## 6. Agents and orchestration (Phase 2–5)

Each agent is a pure-ish function `run(input: XInput, ctx) -> XOutput` with Pydantic schemas carrying `schema_version`. The orchestrator persists a `workflow_run` with a DAG of `workflow_tasks`; each task becomes a job. Scene-level tasks are independent jobs so a failed scene is retried alone. See `AGENT_SPECIFICATIONS.md`.

## 7. Cloud + local strategy

Provider adapters implement capability interfaces (`ScriptGeneration`, `ImageGeneration`, `VideoGeneration`, `SpeechSynthesis`, `SpeechRecognition`, `Embeddings`). A router picks a provider per task from user preference + declared capability + availability. Local-first today: rendering, probing, mixing, subtitles, storage, state. Cloud-first today (4 GB VRAM): image and video generation, premium TTS, high-quality reasoning. See `PROVIDER_INTEGRATION.md` and Phase 6 in `IMPLEMENTATION_PLAN.md`.

## 8. Security posture (Phase 1)

Single-user, API bound to `127.0.0.1`, CORS limited to the web origin. Secrets via `.env` loaded as `SecretStr`, redacted in logs. Audit log for project/settings changes. Multi-user (owner_id on projects, auth) is a future design item; `projects` reserves no owner column yet to avoid fake auth.
